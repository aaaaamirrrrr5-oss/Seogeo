# گزارش انتشار Site Manager AI 4.9.9

## خلاصه
نسخه 4.9.9 بر پایه سورس 4.9.8 ساخته شده و تمرکز آن روی پایداری ممیزی SEO، جلوگیری از اجرای ناخواسته، دقت لینک‌سنجی، کاهش درخواست‌های HTML، نگهداری امن تاریخچه اصلاحات و پوشش post type/taxonomyهای عمومی است. هیچ فایل پوسته Beano Coffee در این نسخه ویرایش نشده است.

## اصلاحات اصلی

### ۱) زمان‌بندی و اجرای ممیزی
- اجرای هفتگی خوداصلاح‌گر به‌صورت پیش‌فرض خاموش است.
- رویداد زمان‌بندی فقط پس از فعال‌سازی مدیر ساخته می‌شود و با خاموش‌کردن تنظیم یا غیرفعال‌سازی افزونه پاک می‌شود.
- رویداد قدیمی ممیزی SEO که در نسخه قبلی بدون انتخاب مدیر ایجاد می‌شد، پاک‌سازی می‌شود.
- هنگام حذف افزونه نیز hookهای زمان‌بندی پاک می‌شوند؛ غیرفعال‌سازی افزونه داده‌های گزارش و تنظیمات را حذف نمی‌کند.
- قفل اجرای خوداصلاح‌گر با `add_option` اتمیک گرفته می‌شود و فقط مالک همان token اجازه آزادسازی دارد.
- انتخاب صفر نوع محتوا به‌معنی اسکن صفر محتواست و دیگر به‌صورت پنهانی به مقاله/برگه بازنمی‌گردد.

### ۲) دقت ممیزی
- لینک‌های `mailto:`, `tel:`, `sms:`, `javascript:`, `data:`, `vbscript:` و fragment-only لینک داخلی محتوایی شمرده نمی‌شوند.
- URL نسبی و مسیر parent نسبت به صفحه مبدأ نرمال می‌شود؛ دامنه خارجی، userinfo و پورت متفاوت به‌عنوان مقصد داخلی پذیرفته نمی‌شوند.
- ویژگی `alt=""` برای تصویر تزئینی معتبر است؛ فقط نبودن ویژگی alt گزارش می‌شود.
- وجود کلمه `schema.org` در متن به‌تنهایی Schema محسوب نمی‌شود؛ تشخیص به JSON-LD یا Microdata واقعی محدود است.
- ممیزی HTML نهایی حداکثر ۱۲ صفحه جدید در هر اجرای SEO را fetch می‌کند؛ نتیجه مثبت/منفی cache می‌شود، timeout محدود و حجم پاسخ سقف دارد و redirect دنبال نمی‌شود.
- در نبود DOMDocument/DOMXPath، تحلیل HTML نهایی به‌عنوان موفق گزارش نمی‌شود.
- خطای ارجاع به متغیر تعریف‌نشده در `rendered_check` رفع شده است.
- اگر متای توضیحات توسط افزونه SEO یا adapter قالب/Beano مدیریت شود، سیستم متای موازی نمی‌نویسد.

### ۳) پوشش محتوا و taxonomy
- ممیزی SEO علاوه بر post/page/product، post typeهای عمومی قابل‌نمایش در پنل را کشف می‌کند؛ انواع سیستمی مانند revision، attachment و templateها حذف می‌شوند.
- ممیزی taxonomy فقط taxonomyهای عمومی و قابل‌مدیریت متصل به نوع محتوای انتخاب‌شده را بررسی می‌کند؛ در صورت انتخاب‌نشدن نوع محتوا، taxonomy نامرتبط وارد گزارش نمی‌شود.

### ۴) Rollback و ثبت سابقه
- rollback فقط زمانی مقدار قبلی را بازمی‌گرداند که مقدار فعلی هنوز برابر مقدار ثبت‌شده پس از اصلاح باشد.
- مواردی که کاربر بعداً تغییر داده یا بازگردانی آن‌ها ممکن نباشد از لاگ حذف نمی‌شوند.
- پیام موفقیت فقط پس از بازگردانی واقعی نمایش داده می‌شود.

## آزمون‌های اجراشده

### PHP / Bridge
- `bash bridge/site-manager-bridge/scripts/check.sh`: موفق.
- PHP lint روی فایل‌های PHP افزونه: موفق، PHP 8.4.24.
- ۹ تست planner/command agent: موفق.
- ۲۲ تست static خوداصلاح‌گر: موفق.
- ۲۸ تست IP client: موفق.
- ۵۰ تست محدودیت کلید: موفق.
- ۱۶ تست link classifier: موفق.
- ۳ تست SEO helper: موفق.
- ۱۷ تست static SEO intelligence: موفق.

### Android / JavaScript
- `npm run check:js`: موفق.
- `npm test`: موفق؛ شامل تست‌های i18n، inline handlerها، backup crypto، CSP/security، WebView، version sync، AI provider، command agent و auto optimizer.
- تست مرورگر: به‌علت نصب نبودن Playwright با وضعیت SKIP رد شد.
- تست DOM: اجرا نشد؛ بسته `jsdom` در محیط نصب نبود و cache محلی برای نصب آفلاین موجود نبود.

## مواردی که هنوز تست نشده‌اند
- نصب و اجرای زنده روی سایت واقعی کاربر یا محیط staging وردپرس.
- سازگاری عملی روی ماتریس نسخه‌های مختلف WordPress، PHP، WooCommerce، Yoast، Rank Math، AIOSEO و قالب Beano.
- اجرای واقعی Ollama/DeepSeek روی سخت‌افزار مقصد.
- اجرای کامل APK روی دستگاه واقعی Android و تست UI مرورگر/DOM.
- دریافت داده واقعی Search Console، GA4، Bing Webmaster Tools، رتبه‌ها، بک‌لینک‌ها یا citation موتورهای مولد، مگر آنکه اتصال رسمی و مجاز جداگانه پیکربندی شود.

## محدوده خوداصلاح‌گر
اصلاح خودکار موجود محدود به تکمیل توضیحات متای خالی با متن موجود همان صفحه است. متن مقاله، عنوان، alt، لینک، قیمت، موجودی، SKU، سفارش، قالب و انتشار عمومی خودکار تغییر داده نمی‌شوند. اصلاحات حساس باید ابتدا پیش‌نمایش و تأیید مدیر داشته باشند.

## محدودیت ادعای کیفیت
هیچ نرم‌افزاری را نمی‌توان بدون آزمون روی سایت و محیط واقعی «بی‌باگ مطلق» دانست. این نسخه از آزمون‌های ذکرشده عبور کرده است، اما موارد تست‌نشده بالا باید قبل از انتشار در سایت اصلی در محیط staging بررسی شوند.
