# گزارش انتشار Site Manager 4.9.6

## آنچه واقعاً اضافه شد
- در اپ، کارت «دستوردهنده و مجری هوشمند سایت» اضافه شده است.
- دستور طبیعی مدیر به endpoint برنامه‌ریزی ارسال می‌شود و مدل JSON محدود تولید می‌کند.
- هدف‌های پشتیبانی‌شده: مقاله، برگه، محصول ووکامرس، جستجو در هر سه نوع و ایجاد پیش‌نویس جدید.
- برای ویرایش، عبارت جستجو لازم است؛ `*` پنج مورد اخیر از نوع انتخاب‌شده را برای یک batch وارد می‌کند.
- حداکثر ۵ هدف در هر طرح؛ هر اقدام به ID و post type واقعی متصل است.
- پیش‌نمایش شامل عنوان/متن فعلی و پیشنهاد است؛ مدیر می‌تواند هر اقدام را جداگانه انتخاب کند.
- هنگام apply، مجوزها و snapshot محتوا دوباره بررسی می‌شوند. تغییر هم‌زمان از زمان preview باعث رد عملیات قدیمی می‌شود.
- محتوای جدید فقط draft می‌شود. به‌روزرسانی محتوای منتشرشده پس از تأیید مدیر انجام می‌شود.
- قیمت، موجودی، SKU، attributeها، سفارش‌ها، افزونه‌ها، تنظیمات، پوسته و فایل‌های Beano Coffee در این عامل قابل تغییر نیستند.
- حالت auto فقط Ollama محلی را صدا می‌زند و به سرویس ابری fallback نمی‌کند.

## آزمون‌ها
- PHP lint افزونه: موفق.
- Bridge quality gate: موفق؛ 28 آزمون IP، 50 آزمون محدودیت کلید، 8 تست SEO و 9 تست static agent.
- `npm test`: موفق؛ تست‌های قبلی پروژه و 13 تست جدید agent.
- `npm run check:js`: موفق؛ بررسی نحو JavaScript و تست‌های مرتبط.
- بسته ZIP افزونه ساخته و با `unzip -t` بررسی شد.

## چه چیزی هنوز آزمایش نشده؟
- اجرای endpointها روی وردپرس واقعی با دیتابیس/کاربر واقعی.
- اتصال Ollama زنده و کیفیت خروجی مدل مشخص روی سایت کاربر.
- اتصال به Search Console، Analytics یا Bing Webmaster Tools.
- تست End-to-End داخل Android/WebView و ساخت APK.
- rollback اختصاصی فرمان‌های AI؛ قبل از استفاده، پشتیبان سایت و Revision وردپرس لازم است.

## پیش‌نیاز هوش مصنوعی بدون API
برای planner زبانی در حالت auto، Ollama و مدل باید روی همان میزبان WordPress و روی loopback اجرا شوند. هاست اشتراکی معمولاً این امکان را ندارد. در آن حالت، تحلیل قاعده‌محور SEO همچنان بدون API کار می‌کند، اما برنامه‌ریزی و تولید محتوا تا زمان فراهم‌شدن Ollama روی میزبان یا انتخاب صریح یک سرویس ابریِ دارای کلید، فعال نخواهد شد.
